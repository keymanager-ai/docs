KryptoVault **Single sign-on** is available as an authentication option for Interactive users.

The current requirements allow administrators to enable SSO access at the individual Interactive-user level.

<Info>
  The provided KeyManager FRD confirms the ability to allow SSO for an Interactive user, but it does not define SSO protocols, identity-provider configuration, claims mapping, domain rules, or certificate/metadata exchange.
</Info>

## SSO-enabled users

Interactive users can be configured with an **Allow SSO** option.

When enabled, the account can use SSO as an authentication method in addition to the supported local authentication flow.

## Relationship with user access

SSO affects how the user authenticates; authorization continues to come from the Roles assigned to that user.

**SSO Authentication → User Account → Assigned Roles → Permissions**

This keeps authentication method and application authorization as separate parts of the access model.

## Configuration scope

The current source requirements do not specify the underlying identity provider, supported SSO protocol, SSO setup workflow, or administrative connection configuration.

Those details should be added when the corresponding SSO requirements are confirmed.
