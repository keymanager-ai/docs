KryptoVault **Secrets** provides centralized management of sensitive values inside Vaults.

A Secret belongs to exactly one Vault and maintains an ordered set of Versions. This allows the Secret to retain a stable identity while its underlying value changes over time.

<Info>
  Secret values are managed through Versions. At most one Version can be the default at a time.
</Info>

## Secret and Vault relationship

Secrets inherit their operating context from the Vault in which they are created.

<CardGroup cols={2}>
  <Card title="Vault Context" icon="vault">
    The Secret belongs to one Vault and follows that Vault's protection, access, expiry, and version-management configuration.
  </Card>

  <Card title="Versioned Value" icon="clock-rotate-left">
    The Secret maintains one or more Versions so value changes can be tracked without replacing the Secret itself.
  </Card>
</CardGroup>

## Secret creation

Creating a Secret also creates its first Version.

<Steps>
  <Step title="Create Secret">
    A permitted user creates a Secret inside a selected Vault.
  </Step>
  <Step title="Version 1 is created">
    KryptoVault automatically creates Version 1 when the Secret is saved for the first time.
  </Step>
  <Step title="Default Version is established">
    One Version acts as the default value used for the Secret.
  </Step>
  <Step title="Additional Versions can be added">
    Later value changes can be stored as new Versions rather than replacing the Secret record.
  </Step>
</Steps>

## Secret Versions

A Secret maintains an ordered Version history.

<Tabs>
  <Tab title="Create Version">
    Additional Versions can be created manually. A new Version can optionally be made the default when it is created.
  </Tab>
  <Tab title="Set Default">
    Only one Version can be marked as the default at a time. Changing the default does not remove the other Versions.
  </Tab>
  <Tab title="Delete Version">
    At least one Version must remain. The active/default Version cannot be deleted until another Version is made the default.
  </Tab>
</Tabs>

## Value changes

Editing the Secret value creates a new Version rather than overwriting the existing Version history.

The updated value becomes a new Version and is made the default, preserving continuity between the Secret identity and its historical values.

<Card title="Versioned Updates" icon="code-branch">
  Secret value changes append a new Version, allowing the previous Versions to remain part of the Secret's history.
</Card>

## Version limits

The Vault can define a maximum number of Versions per Secret.

When the configured limit is reached, KryptoVault applies the Vault's Version-retention rule before another Version is added. The FRD defines FIFO handling with user confirmation when the limit would be exceeded.

<Note>
  Version limits are configured at the Vault level and enforced for each Secret.
</Note>

## Expiry management

Secrets can carry expiry information.

When the Vault requires expiry, every Secret must have a future expiry date. Key Vault configuration can also provide a default expiry duration for new Secrets, while users can still work within the configured expiry rules when updating Secret values.

## Environment context

Key Vault configuration can define a **Default Environment** for new Secrets.

The default is provided as a UI convenience when creating a Secret and can be changed by the user; it is not enforced as a backend restriction.

## Secret value display

Secret values remain protected in normal listing and Vault views.

When a value is viewed, KryptoVault can present it through the Secret detail flow. The product requirements also include JSON detection so valid JSON values can be displayed in a readable structured format, while non-JSON values continue to display as plain text.

## Secret lifecycle

The Secret record and its Versions work together as one managed lifecycle:

**Create Secret → Version 1 → Add / Update Versions → Set Default → Manage Expiry → Retain Version History**

This allows applications and users to work with the current Secret value while KryptoVault maintains the Version history required by the Vault configuration.
