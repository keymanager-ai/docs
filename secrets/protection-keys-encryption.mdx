KryptoVault **Protection Keys** define the cryptographic key configuration used by Vaults to protect Secret values.

Protection Keys are managed separately from Vaults and Secrets. A Vault selects its Protection Key during creation, and that relationship remains fixed for the lifetime of the Vault.

<Info>
  Protection Keys are identified by a unique key identifier. The identifier is immutable after creation.
</Info>

## Protection Key model

A Protection Key contains two identities:

<CardGroup cols={2}>
  <Card title="Key Identifier" icon="fingerprint">
    Provides the unique system-facing identifier used when a Vault links to the Protection Key. It cannot be changed after creation.
  </Card>

  <Card title="Key Name" icon="tag">
    Provides a human-friendly name for identifying the Protection Key in Key Vault management.
  </Card>
</CardGroup>

## Protection Key types

The KeyManager requirements define three Protection Key types.

<Tabs>
  <Tab title="Local">
    Uses a local Fernet key as the key material.

    The local key value is stored encrypted and displayed in masked form in the user interface.
  </Tab>
  <Tab title="AWS KMS">
    Defines an AWS KMS-based Protection Key using an AWS region and KMS Key ID or ARN.
  </Tab>
  <Tab title="HashiCorp">
    Defines a HashiCorp-based Protection Key using the configured HashiCorp connection information.
  </Tab>
</Tabs>

<Note>
  The Sprint 3 requirements state that **Local** is the applicable Protection Key type at that stage, while AWS KMS and HashiCorp are defined in the data model and configuration requirements.
</Note>

## Local key protection

For Local Protection Keys, KryptoVault uses a Fernet key.

<Steps>
  <Step title="Generate or provide valid key material">
    The Local Protection Key uses a valid Fernet key.
  </Step>
  <Step title="Store the key securely">
    The key value is stored encrypted rather than as readable plaintext.
  </Step>
  <Step title="Mask sensitive key material">
    The Fernet key is masked in the user interface.
  </Step>
  <Step title="Link the key to a Vault">
    The Protection Key becomes available for selection when a Vault is created.
  </Step>
</Steps>

## Relationship with Vaults

Protection Keys and Vaults are separate management objects.

**Protection Key → Vault → Secrets → Versions**

A Vault references the selected Protection Key by its key identifier. Once the Vault is created, the linked Protection Key cannot be replaced.

<Card title="Fixed Vault Protection" icon="shield-keyhole">
  The Protection Key selected during Vault creation remains the Vault's Protection Key throughout the Vault lifecycle.
</Card>

## Sensitive-data handling

Protection Key material is treated as sensitive information.

The product requirements require sensitive values such as Fernet keys to be masked in the UI. This keeps key configuration visible for management purposes without exposing the underlying key material.

## Protection Key lifecycle

Permitted users can create, view, update, and delete Protection Keys according to the defined Key Settings behavior.

The unique key identifier remains immutable, allowing Vault references to remain stable even when editable Protection Key information is updated.
